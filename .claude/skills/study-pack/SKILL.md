# study-pack: 학습 자료와 발표 자료

한 주제의 **내용 폴더** 하나에서 결과물 넷을 만듭니다. 화면 틀은 템플릿으로 고정되어 있고, 매번 쓰는 것은 내용뿐입니다.

```
week-NN/<이름>/study-pack/
  content.json    제목, 카드 묶음, 카드
  study.html      정리 노트 본문
  slides.html     장표 조각 (<section> 이어 쓰기)
week-NN/<이름>/
  flashcards.html         ← build.py: 정리 노트 + 암기 카드 (아티팩트로 게시)
  slides.html, <제목>.pdf  ← slides.py: 발표 장표
  발표 대본.md, demo.sh     ← 직접 씀
```

- **학습 자료**를 달라고 하면 정리 노트 + 암기 카드, **발표 자료**를 달라고 하면 장표 + 대본 + 데모. 사용자가 그 주 발표자이고 범위를 말하지 않으면 넷 다 만듭니다. 장표와 대본은 정리 노트와 같은 순서·같은 문장으로 만들어, 셋이 서로 어긋나지 않게 합니다.
- **다 쓴 예이자 수준의 기준**: `week-04/유진영/` (캐시·ETag), `week-05/유진영/` (WebSocket, 직접 만든 데모 서버 `ws-demo/` 포함). 처음 만들 때 `study-pack/` 세 파일, `발표 대본.md`, `demo.sh`를 먼저 읽고 깊이와 문체를 맞춥니다.
- **"내일 스터디 준비해 줘"**처럼 범위 없이 오면: 그 주 발표 자료 넷 + 지난주 과제(장표 2~3에 쓸 결과)를 함께 준비합니다. 회차가 애매하면 한 번 묻습니다.

## 수준: 처음 배우는 사람 (ELI15, 개발 초보자)

독자는 처음 배우는 사람입니다. 사용자가 "설명이 부족하다"고 한 곳은 늘 앞 단계를 건너뛴 곳이었습니다(예: 요청에 실리는 Cache-Control을 설명 없이 꺼내자 "서버만 보내는 헤더 아니었나?" 하고 막힘). 노트·카드·장표·대본 모두에 적용합니다.

- **바탕부터**: 주제가 기대는 개념(예: 요청·응답·헤더·본문)을 먼저 풀고, 오늘 나오는 용어·헤더를 한 표에 모읍니다. 헤더·필드·메시지에는 **누가 보내는지, 어디에 싣는지**(요청/응답, 클라이언트/서버)를 꼭 밝힙니다.
- **주제 이름부터 정의**: "캐시가 뭔가"처럼 주제 자체를 한 문장으로 정의하고, **왜 필요한지**와 **그 대신 생기는 문제**를 말한 뒤 세부로 들어갑니다.
- **개념마다 같은 순서**: 왜 필요한가 → 비유 → 실제 모습(헤더, 명령 출력) → 함정.
- **용어는 처음 나올 때 풀어 씁니다**(CDN, 리버스 프록시, 해시, 멱등…). 이름은 같은데 자리에 따라 뜻이 다른 것(같은 헤더가 요청과 응답에서 다른 뜻)은 나란히 놓고 함정으로 짚습니다.
- **분량의 기준**(4주차 예): 정리 노트 단원 8개 + 마지막 정리, 카드 83장(묶음마다 8~12장), 장표 19장(17분), 대본은 장표마다 꼭 말할 문장.

## 1. 범위와 재료

1. 몇 주차, 어떤 주제인지 정합니다. 이 저장소는 일정이 자주 밀리니 루트 `README.md` 날짜보다 마지막 `week-NN` 폴더와 사용자의 말을 믿습니다.
2. 재료를 읽습니다: 루트 `README.md`의 그 주차 항목(진단 퀴즈 Q번호, 책 범위, 과제, 발표 규칙), 그 주차 폴더의 노트·장표·과제 README, 지난주 과제 결과.
3. 재료가 비면 공식 문서(MDN, RFC 등)로 채우고 출처를 카드 `s`에 적습니다.
4. 명령으로 확인할 수 있는 사실(curl 헤더, 크기, 상태 코드)은 직접 돌려 실측값과 날짜를 씁니다.

**끝난 기준**: 단원 목록 6~9개가 정해졌고(첫 단원은 바탕, 둘째는 주제 정의), 진단 퀴즈 Q번호마다 답하는 단원이 있습니다.

## 2. 정리 노트 (`study.html`)

부품과 마크업은 [COMPONENTS.md](COMPONENTS.md)에 있습니다. 목소리는 **쪽집게 과외 선생님**입니다. 범위를 좁혀 주고, 시험에 나올 것을 짚고, 다들 틀리는 곳에서 멈춰 세웁니다.

- 맨 위(hero): 오늘 범위를 문제 두세 개로 묶는 한 문단, 상자 읽는 법, "암기 카드로 복습하기" 버튼, 단원 목차.
- 단원마다:
  - 맨 위에 **외울 한 문장**(`.one`). 이 문장만 읽어도 단원이 남게 씁니다.
  - 퀴즈 문항이 있으면 머리말에 `Q번호`를 달고 그 단원 안에서 답을 분명히 말합니다.
  - 헷갈리는 짝은 `.vs`, 순서는 `.seq`, 갈래는 `.fork`, 값 목록은 표로 그립니다. 글로 길게 풀기 전에 그림이 되는지 봅니다.
  - 상자를 섞어 씁니다: **쪽집게**(꼭 외울 것), **함정**(다들 틀리는 것), **외우는 법**(비유·대비·요령), **출제 예상**(Q/A, 계산 문제, 발표 뒤 나올 질문).
  - 끝에 그 단원 카드 묶음으로 가는 버튼.
- 지난주 과제와 이어지는 곳은 단원 하나로 짧게.
- 맨 끝은 **시험 직전 5문장**(`unit final`): 입으로 말할 수 있어야 하는 다섯 줄과 카드 버튼.
- 문체는 쉬운 한국어. 설명은 "~합니다", 외울 문장은 "~다"로 짧게. 실측값에는 날짜를 붙입니다.

**끝난 기준**: 모든 단원에 한 줄 요약과 카드 버튼이 있고, 상자 네 종류가 다 있고, 바탕 단원에 "누가 보내나" 표가 있습니다.

## 3. 암기 카드 (`content.json`)

```json
{
  "title": "브라우저 탭 이름 (두세 낱말, 주제를 알아볼 낱말 포함)",
  "slides_title": "장표 제목 (PDF 파일 이름)",
  "brand": "5주차 · 주제",
  "storage_key": "w5-flash-v1",
  "card_eyebrow": "NETWORK STUDY · WEEK 5 · Q30 · Q32",
  "card_title": "주제 암기 카드",
  "study": "study.html",
  "decks": [{ "id": "ws", "name": "3 WebSocket · Q32" }],
  "cards": [{ "d": "ws", "q": "앞면 질문", "a": "뒷면 한 줄 답", "n": ["덧붙임 문단"], "c": "코드나 출력", "s": "출처" }]
}
```

- **묶음은 단원과 하나씩**, 이름 앞에 단원 번호. 묶음 id는 영어 소문자·숫자·하이픈(주소 `#cards-<id>`에 씀).
- 묶음마다 8~12장, 전체 70~90장. 노트의 한 줄 요약, 함정, 출제 예상, 퀴즈 문항은 빠짐없이 카드가 됩니다.
- `q`는 소리 내어 답할 수 있는 질문. `a`는 한 줄 답. `n`은 이유·예·주의. `c`는 실측 출력이나 명령. `s`는 노트 단원, 실측 날짜.
- 카드 뒷면만 읽어도 막히지 않게 `a`·`n`에 주어(누가)와 방향(요청/응답)을 씁니다.
- `q`·`a`·`n` 안에서는 `<code>`, `<b>`를 씁니다. `c`는 글자 그대로 나옵니다.
- `storage_key`는 페이지마다 다르게(`w<주차>-flash-v1`). 카드 표시는 배열 순서 번호로 저장됩니다. 카드를 통째로 새로 짜면 끝 숫자를 올리고, 이미 공부 중인 페이지에 카드를 더할 때는 **배열 맨 끝에 붙입니다**(중간에 끼우면 뒤 카드들의 "알아요/다시"가 한 칸씩 밀림). 고치기만 할 때는 자리를 그대로 둡니다.

**끝난 기준**: 노트의 모든 단원·상자에 대응하는 카드가 있습니다.

## 4. 발표 장표 (`slides.html`), 대본, 데모

[SLIDES.md](SLIDES.md)에 장표 순서, 부품, 대본·데모 형식이 있습니다. 장표는 정리 노트 단원 순서를 따르고, 한 장표의 핵심 문장은 노트의 한 줄 요약과 같게 씁니다.

**끝난 기준**: 장표에 표지 → 지난주 과제 2장 → 퀴즈 → 바탕 → 주제 정의 → 본론 → 직접 보기 → 정리("우리 서비스에서는")가 다 있고, 대본의 장표 번호·시간표가 장표와 맞고, 데모가 실제로 돕니다(`bash demo.sh`를 끝까지 한 번).

## 5. 빌드와 확인

```bash
python3 .claude/skills/study-pack/build.py  week-NN/<이름>/study-pack week-NN/<이름>/flashcards.html
python3 .claude/skills/study-pack/slides.py week-NN/<이름>/study-pack week-NN/<이름>
```

- 오류를 적으면 고쳐서 통과할 때까지 다시 돌립니다. `slides.py`는 PDF 쪽수와 장표 수가 다르면(넘친 장표) 멈춥니다.
- 정리 노트는 Chrome 헤드리스로 위쪽을 한 번 찍어 봅니다(`--screenshot`, 창 1000×4200, 주소에 `#` 없이). 장표는 `slides.py`가 찍은 `overview.png` 한 장을 봅니다. 깨진 곳만 고칩니다.

**끝난 기준**: 두 빌드가 단원·카드·장표 수를 찍고 끝났고, 두 이미지에 넘치거나 겹친 곳이 없습니다.

## 6. 게시와 알리기

1. `flashcards.html`을 아티팩트로 게시합니다. 이 세션에서 처음이면 artifacts 서버의 `guide`를 먼저 읽습니다. `publish_files`로 `index.html`에 올립니다(제목은 `title`, 아이콘 `cards`).
2. 다시 고칠 때는 같은 아티팩트에 올립니다. 처음 게시한 뒤 `content.json`에 `"artifact_slug"`를 적어 두고 다음엔 그 slug로 올립니다.
3. 그 주차 `README.md`의 자료 목록을 맞춥니다(장표 장수와 흐름, 정리 노트 단원·카드 수, 대본, 데모). 장표 번호를 적은 곳(README 체크리스트, `demo.sh` 주석)도 새 번호로 고칩니다.
4. GitHub main까지 올려야 끝납니다(팀원이 GitHub에서 자료를 봅니다). 묻지 않고 작업 브랜치 → 커밋 → 푸시 → PR → 머지 → 로컬 main 동기화 → 합쳐진 브랜치 로컬·원격 삭제까지 합니다.
5. 사용자에게 아티팩트 링크, PR 링크, 무엇을 바꿨는지, 단원·카드·장표 수를 짧게 알립니다.

## 템플릿을 고칠 때

디자인이나 동작을 바꿔 달라고 하면 템플릿을 고칩니다. 정리 노트·카드는 `assets/template.html`(자리 표시 `{{TITLE}}` `{{BRAND}}` `{{STUDY}}` `{{CARD_EYEBROW}}` `{{CARD_TITLE}}` `{{DECKS_JSON}}` `{{CARDS_JSON}}` `{{STORAGE_KEY_JSON}}`), 장표는 `assets/slides-template.html`(`{{TITLE}}` `{{SLIDES}}`). 자리 표시 글자는 주석에도 쓰지 않습니다(빌드가 모든 자리를 바꿉니다). 고친 뒤에는 4주차를 다시 빌드해 같은 모양인지 봅니다.
