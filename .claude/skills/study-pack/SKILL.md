# study-pack: 정리 노트 + 암기 카드

결과물은 HTML 한 장입니다. 첫 화면은 **쪽집게 과외 선생님**이 쓴 정리 노트이고, "암기 카드로 복습하기"를 누르면 같은 내용을 앞뒷면 카드로 복습합니다. 화면 틀(디자인, 카드 뒤집기, 묶음, "알아요/다시" 표시, 목록)은 `assets/template.html`에 고정되어 있습니다. 매번 쓰는 것은 **내용 폴더** 하나뿐입니다.

```
week-NN/<이름>/study-pack/
  content.json   제목, 카드 묶음, 카드
  study.html     정리 노트 본문
week-NN/<이름>/flashcards.html   ← build.py가 만든 결과
```

다 쓴 예: `week-04/유진영/study-pack/` (4주차 캐시·ETag, 단원 6개, 카드 63장). 처음 만들 때 이 두 파일을 먼저 읽고 수준과 문체를 맞춥니다.

## 1. 범위와 재료

1. 몇 주차, 어떤 주제인지 정합니다. 이 저장소는 일정이 자주 밀리니 루트 `README.md` 날짜보다 마지막 `week-NN` 폴더와 사용자의 말을 믿습니다.
2. 재료를 읽습니다: 루트 `README.md`의 그 주차 항목(진단 퀴즈 Q번호, 책 범위, 과제), 그 주차 폴더의 스터디 노트·장표·발표 대본·과제 README, 지난주 과제 결과.
3. 재료가 비면(아직 발표 준비 전인 주제) 공식 문서(MDN, RFC 등)로 채우고, 출처를 카드 `s`에 적습니다.
4. 명령으로 확인할 수 있는 사실(curl 헤더, 크기, 상태 코드)은 직접 돌려 실측값과 날짜를 씁니다.

**끝난 기준**: 단원 목록 3~7개가 정해졌고, 진단 퀴즈 Q번호마다 답하는 단원이 하나씩 있습니다.

## 2. 정리 노트 쓰기 (`study.html`)

부품과 마크업은 [COMPONENTS.md](COMPONENTS.md)에 있습니다. 목소리는 **쪽집게 과외 선생님**입니다. 범위를 좁혀 주고, 시험에 나올 것을 짚고, 다들 틀리는 곳에서 멈춰 세웁니다.

- 맨 위(hero): 오늘 범위를 문제 두세 개로 묶는 한 문단, 상자 읽는 법, "암기 카드로 복습하기" 버튼, 단원 목차.
- 단원마다:
  - 맨 위에 **외울 한 문장**(`.one`). 이 문장만 읽어도 단원이 남게 씁니다.
  - 퀴즈 문항이 있으면 머리말에 `Q번호`를 달고 그 단원 안에서 답을 분명히 말합니다.
  - 헷갈리는 짝은 `.vs`, 순서는 `.seq`, 갈래는 `.fork`, 값 목록은 표로 그립니다. 글로 길게 풀기 전에 그림이 되는지 봅니다.
  - 상자를 섞어 씁니다: **쪽집게**(꼭 외울 것), **함정**(다들 틀리는 것), **외우는 법**(비유·대비·줄임말), **출제 예상**(Q/A, 계산 문제, 발표 뒤 나올 질문).
  - 끝에 그 단원 카드 묶음으로 가는 버튼.
- 지난주 과제와 이어지는 곳이 있으면 단원 하나로 짧게 둡니다.
- 맨 끝은 **시험 직전 5문장**(`unit final`): 입으로 말할 수 있어야 하는 다섯 줄과 카드 버튼.
- 문체는 쉬운 한국어. 설명은 "~합니다", 외울 문장은 "~다"로 짧게. 실측값에는 날짜를 붙입니다.

**끝난 기준**: 모든 단원에 한 줄 요약과 카드 버튼이 있고, 노트 전체에 상자 네 종류가 다 있고, 각 함정·출제 예상이 무엇을 묻는지 카드로 옮길 수 있을 만큼 구체적입니다.

## 3. 카드 쓰기 (`content.json`)

```json
{
  "title": "브라우저 탭 이름 (두세 낱말, 주제를 알아볼 낱말 포함)",
  "brand": "5주차 · 주제",
  "storage_key": "w5-flash-v1",
  "card_eyebrow": "NETWORK STUDY · WEEK 5 · Q30 · Q32",
  "card_title": "주제 암기 카드",
  "study": "study.html",
  "decks": [{ "id": "ws", "name": "WebSocket · Q32" }],
  "cards": [{ "d": "ws", "q": "앞면 질문", "a": "뒷면 한 줄 답", "n": ["덧붙임 문단"], "c": "코드나 출력", "s": "출처" }]
}
```

- **묶음은 단원과 하나씩** 맞춥니다. 묶음 id는 영어 소문자·숫자·하이픈(주소 `#cards-<id>`에 씀).
- 묶음마다 8~12장, 전체 40~70장. 노트의 한 줄 요약, 함정, 출제 예상, 퀴즈 문항은 빠짐없이 카드가 됩니다.
- `q`는 소리 내어 답할 수 있는 질문. `a`는 한 줄 답(외울 문장). `n`은 이유·예·주의. `c`는 실측 출력이나 명령. `s`는 장표 번호, 노트, 실측 날짜.
- `q`·`a`·`n` 안에서는 `<code>`, `<b>`를 쓸 수 있습니다. `c`는 글자 그대로 나옵니다.
- `storage_key`는 페이지마다 다르게(`w<주차>-flash-v1`). 같아지면 다른 주차의 "알아요" 표시가 섞입니다.

**끝난 기준**: 노트의 모든 단원·상자에 대응하는 카드가 있습니다.

## 4. 빌드와 확인

```bash
python3 .claude/skills/study-pack/build.py week-NN/<이름>/study-pack week-NN/<이름>/flashcards.html
```

빌드가 오류를 적으면 고쳐서 통과할 때까지 다시 돌립니다. 통과하면 Chrome 헤드리스로 정리 노트 화면을 한 번 찍어 보고(`--screenshot`, 창 1000×3000), 깨진 곳만 고칩니다.

**끝난 기준**: 빌드가 단원 수·카드 수를 찍고 끝났고, 스크린숏에서 넘치거나 겹친 곳이 없습니다.

## 5. 게시와 알리기

1. 아티팩트로 게시합니다. 이 세션에서 처음이면 artifacts 서버의 `guide`를 먼저 읽습니다. `publish_files`로 `flashcards.html`을 `index.html`로 올립니다(제목은 `title`, 아이콘 `cards`).
2. 다시 고칠 때는 같은 아티팩트에 올립니다. 처음 게시한 뒤 `content.json`에 `"artifact_slug"`를 적어 두면 다음에 그 slug로 다시 게시합니다(빌드는 이 칸을 무시합니다).
3. 그 주차 `README.md`의 자료 목록에 `flashcards.html` 한 줄을 더합니다.
4. 사용자에게 링크, 단원·묶음별 카드 수, 쓰는 법(뒤집기, 알아요/다시, 섞기, 뒷면 먼저)을 짧게 알립니다. 커밋은 요청이 있을 때만 합니다.

## 템플릿을 고칠 때

디자인이나 동작을 바꿔 달라고 하면 `assets/template.html`을 고칩니다. 자리 표시는 `{{TITLE}}`, `{{BRAND}}`, `{{STUDY}}`, `{{CARD_EYEBROW}}`, `{{CARD_TITLE}}`, `{{DECKS_JSON}}`, `{{CARDS_JSON}}`, `{{STORAGE_KEY_JSON}}`입니다. 고친 뒤에는 4주차 예시를 다시 빌드해 보고, 이미 만든 주차 페이지도 다시 빌드해 같은 모양을 유지합니다.
