① 멱등 POST
같은 키로 두 번 = 주문 1건

두 번째는 저장해 둔 첫 응답을 그대로 돌려준다(Idempotent-Replayed: true). 처리 중에 또 오면 409, 키는 같은데 본문이 다르면 422.

② 500 · 504
500은 앱, 504는 nginx

예외 → 500 JSON(0.000초). 4초 걸리는 핸들러 → 정확히 2.00초에 504 HTML. 느린 POST가 504로 끝나도 같은 키로 재시도하면 주문은 1건.

③ 502
거절당하면 502

응답 도중 연결 끊기 → prematurely closed. 127.0.0.1 바인딩 → Connection refused. 둘 다 0.002초 안에 502.

03

내 로그인 화면, 내 장바구니. 나에게만 맞는 응답. 브라우저만 저장해야 한다.

배경 지식 2 / 3

저장한 응답에는 유통기한이 있다

응답 (MDN, 오늘 받은 것)HTTP/2 200 cache-control: public, max-age=3600 age: 1254 etag: "5db9819de628…"

max-age=3600: 받은 뒤 1시간 동안은 신선(fresh)하다. 서버에 묻지 않고 그냥 쓴다.

age: 1254: CDN이 이 응답을 들고 있은 지 1254초. 남은 신선 시간은 3600 − 1254 = 약 39분.

기한이 지나면 상했다(stale). 바로 버리지 않고, 다음 장의 "확인"을 거친다.

우유 유통기한과 같다. 기한 안이면 그냥 마시고, 지나면 냄새를 맡아 보고(재검증) 괜찮으면 또 마신다.

Q20

no-cache는 "저장 금지"가 아니다

no-cache
저장 OK, 쓰기 전에 매번 확인

신선 기간 0과 같다. 매번 서버에 묻지만, 안 바뀌었으면 304로 본문을 아낀다. "항상 최신이어야 하는" HTML에 맞다.

no-store
아예 저장하지 마

디스크에도 남기지 않는다. 매번 본문 전체를 받는다. 계좌 내역, 개인정보 화면처럼 남으면 안 되는 응답에만.

함정: 이름 때문에 "캐시 끄기 = no-cache"로 쓰는 경우가 많다. 진짜로 끄려면 no-store, 항상 최신만 원하면 no-cache가 304 덕분에 더 싸다.

Q21

ETag → If-None-Match → 304

브라우저
→ GET /orders/7
200 OK · ETag: "v3" · 본문 2KB ←
… 신선 기간이 지났다 …
→ GET /orders/7 · If-None-Match: "v3"
304 Not Modified · 본문 없음 ←
서버
ETag

서버가 응답에 붙이는 내용의 지문. 내용이 바뀌면 값도 바뀐다. 해시나 버전 번호로 만든다.

If-None-Match

"내가 가진 건 이 지문인데, 이것과 다르면 보내 줘." 같으면 서버는 304로 "가진 거 써"라고만 한다.

직접 보기 · curl

MDN 첫 화면: 117KB가 0바이트로

① 처음 받기$ curl -s -o /dev/null -D - \ https://developer.mozilla.org/en-US/ HTTP/2 200 etag: "5db9819d…" cache-control: public, max-age=3600 본문 116,977 B (gzip이면 16,430 B)
② 지문을 들고 다시 묻기$ curl -s -o /dev/null -D - \ -H 'If-None-Match: "5db9819d…"' \ https://developer.mozilla.org/en-US/ HTTP/2 304 etag: "5db9819d…" 본문 0 B · 0.03초

연결·왕복은 그대로 든다. 아끼는 건 본문 전송이다. 그래서 "아예 안 묻는" max-age와 같이 쓴다.

협상 + 캐시

Vary: 캐시에게 "이 헤더도 보고 구분해"

캐시는 기본으로 주소만 보고 같은 응답인지 판단한다. 그런데 협상을 하면 같은 주소에 응답이 여러 개다.

Vary: Accept-Language를 붙이면 캐시가 주소 + 그 헤더 값을 묶어 따로 저장한다.

거의 모든 사이트가 Vary: Accept-Encoding을 붙인다. 압축 응답과 비압축 응답을 섞지 않기 위해서다.

Vary를 빼먹으면
· 한국인이 먼저 받은 한국어 페이지가 CDN에 저장되고, 다음 미국인도 한국어를 받는다
· gzip 못 읽는 클라이언트가 압축된 본문을 받는다
· 로그인 사용자 화면이 남에게 간다 → 이건 Vary가 아니라 private로 막는다

규칙 하나: 내용이 바뀌면 주소가 바뀌는 파일(해시·버전)은 길게, 주소는 그대로인데 내용이 바뀌는 HTML·API는 짧게 + ETag.

정리

  1. 캐시는 신선하면 묻지 않고, 상하면 지문(ETag)을 들고 묻고, 안 바뀌었으면 304를 받는다.
  2. no-cache는 매번 확인, no-store는 저장 금지. 내 것이면 private.
  3. 같은 주소에 다른 응답(협상)을 주면 Vary를 붙인다.
  4. 버전이 박힌 파일은 1년, HTML·API는 짧게 + ETag.
