# 과제 A. TCP 에코 서버 · 유진영

## 무엇을 만들었나

HTTP 프레임워크 없이 Python 표준 라이브러리 `socket`만으로 만든 TCP 에코 서버와 테스트용 클라이언트입니다.

| 파일 | 하는 일 |
| --- | --- |
| `echo_server.py` | `--host`로 받은 주소에 바인딩하고, 접속한 클라이언트의 IP·포트를 로그로 남기며 받은 데이터를 그대로 돌려준다 |
| `echo_client.py` | 클라이언트 여러 개를 동시에 붙여서 각자의 출발지 포트와 답장을 출력한다 |

Python 3.8 이상이면 추가 설치 없이 돌아갑니다.

```bash
python3 echo_server.py                    # 127.0.0.1:9000
python3 echo_server.py --host 0.0.0.0     # 모든 주소
python3 echo_client.py --count 3          # 다른 터미널에서
nc 127.0.0.1 9000                         # 손으로 쳐 보기
```

## 무엇을 확인했나

### 1. 동시에 붙은 클라이언트 3개는 출발지 포트가 모두 다르다

```
client#2  출발지 127.0.0.1:46942  ->  127.0.0.1:9000  답장 'hello from client#2'
client#1  출발지 127.0.0.1:46950  ->  127.0.0.1:9000  답장 'hello from client#1'
client#3  출발지 127.0.0.1:46958  ->  127.0.0.1:9000  답장 'hello from client#3'
```

서버 쪽 로그 (연결 줄만 발췌):

```
[12:50:28] 서버 시작 127.0.0.1:9000 에서 기다리는 중
[12:50:29] 연결됨   client=127.0.0.1:46942
[12:50:29] 연결됨   client=127.0.0.1:46950
[12:50:29] 연결됨   client=127.0.0.1:46958
```

목적지(127.0.0.1:9000)는 셋 다 같지만 출발지 포트가 달라서 서버는 세 연결을 따로 구분합니다. 진단 퀴즈 Q07(출발지 포트는 OS가 임시로 고른다)을 직접 확인한 결과입니다.

### 2. 127.0.0.1에 바인딩하면 다른 주소로는 접속이 거부된다

| 서버 바인딩 | 127.0.0.1로 접속 | 내 기기의 다른 IP로 접속 |
| --- | --- | --- |
| `127.0.0.1` | 성공 | `Connection refused` |
| `0.0.0.0` | 성공 | 성공 |

```
# 127.0.0.1 바인딩, 기기의 다른 IP로 접속
client#1 연결 실패: [Errno 111] Connection refused

# 0.0.0.0 바인딩, 같은 IP로 접속
client#1  출발지 192.0.2.2:44288  ->  192.0.2.2:9000  답장 'hello from client#1'
```

> 위 로그는 테스트 환경의 예시입니다. 발표 전에 내 노트북에서 다시 돌려 이 자리를 내 결과로 바꿉니다. 휴대폰으로 확인할 때는 `ipconfig getifaddr en0`(macOS)로 노트북 IP를 찾아 `nc <IP> 9000`(휴대폰 터미널 앱) 또는 같은 와이파이의 다른 노트북에서 `python3 echo_client.py --host <IP>`를 실행합니다.

## 예상과 달랐던 점

- 클라이언트 번호 순서(#1, #2, #3)와 서버가 연결을 받은 순서가 달랐다. 스레드 3개가 동시에 출발하면 누가 먼저 핸드셰이크를 끝낼지는 정해져 있지 않다.
- 출발지 포트가 46942, 46950, 46958처럼 크고 가까운 숫자였다. 리눅스는 기본적으로 32768~60999 범위의 임시 포트에서 고른다. (macOS는 49152~65535)
- [내 노트북에서 돌려 보고 느낀 점을 한 줄 추가]

## 2주차와 이어지는 부분

- 서버를 끄고 바로 다시 켜면 `Address already in use`가 날 수 있는데, 먼저 끊은 쪽에 남는 **TIME_WAIT** 때문이다. 그래서 `SO_REUSEADDR`를 켰다. 2주차 주영님 발표 주제.
- `accept()`가 돌려주는 연결은 이미 3-way handshake를 마친 연결이다. 과제 B에서 이 서버에 접속하는 과정을 와이어샤크로 캡처한다.
