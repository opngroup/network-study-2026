1. 브라우저가 서버에 붙을 때 출발지 포트는 누가, 어떤 포트를 선정해서 서버로 보내는가?

- 포트 번호 범위
  - 잘 알려진 포트 (0~1023)
  - 등록된 포트 (1024 ~ 49151)
  - 동적포트 (49152~65535)
- 임시 포트 : 클라이언트 쪽 포트는 OS가 빈 번호를 골라줍니다!?
- 소켓 식별 4-튜플 : 출발지 IP, 출발지 포트, 목적지 IP, 목적지 포트
  - 같은 서버에 탭 3개를 열어도 연결이 섞이지 않는 이유가 이것이라는데?
- 확인 명렬 : sysctl net.inet.ip.portrange.first net.inet.ip.portrange.last (macOS)

2. 공유기 뒤의 노트북 3대가 같은 사이트에 동시에 접속하면, 공유기는 돌아온 응답을 어느 노트북에 줄지 어떻게 아나요?

- 사설 IP vs 공인 IP: 10.c, 172.16~31.x, 192.168.c 대역
- NAT: 사설 IP를 공인 IP로 바꿔 내보내는 것
- NAPT (PAT, IP 마스커레이드): IP 뿐 아니라 포트까지 바꿔서, 공인 IP 하나를 여러 기기가 나눠쓴다.?
- NAT 변환 테이블 : 내부 IP:포트 <-> 공인 IP:바뀐 포트를 적어둔 표.

3. 서버가 공유기 뒤의 클라이언트에 먼저 연결할 수 없는 이유는 뭔가요? (두 분 다 틀린 Q07입니다)

- 변환 테이블 항목은 안에서 나갈 때 생긴다? 밖에서 먼저 온 패킷은 테이블에 짝이 없어서 버려진다?
- 인바운드 vs 아웃 바운드
- 그래서 생긴 우회책
  - 포트 포워딩 : 테이블에 미리 고정 항목을 적어둔다.
  - NAT 트래버설 / 홀 펀칭 / STUN-TURN: WebRTC가 쓰는 방식
  - 서버 푸시는 클라이언트가 먼저 연결을 열어둔다. : 5주차 SSE / WebSocket과 이어진다.

- 출발지 포트를 OS가 고르는 방식
- NAPT 변환 테이블
- 서버가 클라이언트에 먼저 연결할 수 없는 이유
